# Phosphor

A browser instrument for psychedelic generative visuals. Fourteen scene families share live controls, per-scene colors, layered effects, music response, portable sets, and visual export.

[Open the public preview](https://phosphor-visual-instrument.fabian523417.chatgpt.site/). The public Site remains version 6. This checkout contains an unreleased recursive-passage and camera repair; see [flight repair evidence](docs/releases/recursive-passages.md). Historical deployment evidence is in [the v6 record](docs/releases/performance-score.md).

## Play

```sh
npm run build
npm run preview
```

Open `http://localhost:48101`. Choose a scene and an authored look. Shape it with the controls, choose a color collection or edit all three colors, then add effects. Artwork colors never change the interface text or controls. Each scene remembers its own palette.

Try **Julia Observatory** for complex fractal filaments; **Fourth Dimension → Hopf lantern** for linked circles rotating through four dimensions; or **Hyperbolic Loom** for geodesics flowing through a Poincaré disk. **Trip stack** combines kaleidoscope, echo trails, chromatic split, and glow. Each layer has an independent strength; Clear effects returns to the raw scene. This stack processes one active scene; mixing several independent scene generators is future work.

The original ten families remain: Acid Mycelium, Causal Tapestry, Feedback Chapel, Magnetic Choir, Cathedrals of Error, Alien Aquarium, Interference Rituals, Topological Melt, Phase Transition Theatre, and Evolution Garden. Julia Observatory, Fourth Dimension, Hyperbolic Loom, and Fractal Flight extend the library with complex filaments, a 4D tesseract/Hopf instrument, hyperbolic geodesics, and a navigable five-level recursive sponge. Topological Melt now rotates and morphs a projected 3D loop with working view, thickness, and color controls. Phase Transition Theatre now sustains moving spatial patterns; Play journey animates its controls, while Manual controls gives them back to you. It is an artistic driven field, not a thermodynamic simulation.

Use Pause to compose a still, Shift + left/right to change scenes, B for blackout, and Focus canvas for an immersive view. Explore exposes every control; Perform keeps a smaller set. Name the set, then add cues to capture the current scene look, palette, and effects; preview any cue, duplicate it, rename it, move it up or down, and edit its bar count (1–64) for timing. Cue ordering, edits, and set identity are saved with the set; use the cue refresh control to update one safely. The cue list exposes each cue’s position and announces the selected step for assistive technology; previewing or playing a long set keeps that active row in view without stealing focus. The set footer shows both clock time and total bars as you compose, plus the active cue name, remaining time, and LIVE/PAUSED state during rehearsal. When the last cue finishes, it stays visibly COMPLETE and the transport button becomes Restart set until you start again. Save set for local persistence; the panel announces the last local-save time, and a dirty session flushes once more when the tab is hidden or closed. Restore previous set recovers the last persisted tab state, and Export JSON reopens it elsewhere; exported filenames use a safe version of the set name. The explicit Load 24m score action provides a nine-cue, three-look rehearsal example and exports the loaded score itself; it does not run until selected. Three-, ten-, and thirteen-scene saves migrate to the fourteen-family library.

The stage overlay mirrors the same transport vocabulary (`LIVE`, `SET LIVE`, `SET PAUSED`, `SET COMPLETE`, `PAUSED`, `BLACKOUT`, or `RECOVERING`) so a cue preview cannot look like an unqualified live set. During a visual scene transition it keeps both facts visible, for example `SET LIVE · MORPHING`; a global visual pause takes precedence so the canvas state remains truthful.

## Fractal Flight — local repair awaiting release

Drag the stage to look; W/S move forward or reverse, A/D strafe, Q/E descend or rise, and arrow keys turn the view. Visible hold buttons support pointer/touch operation. Start cruise moves along your heading; Cruise turn adds a steady turning rate. Release held controls to stop manual movement. Pause, blackout, switching scenes, leaving the window or hiding the tab, and reopening a set stop movement. Reset to entrance recovers a clear viewpoint. Near surfaces, travel stops; reverse or turn to leave the boundary.

The environment is a five-level recursive sponge repeating every six world units in all directions, with connected passages. It is not infinite unique geometry. Passage width changes the openings; if narrowing would enclose the camera, the view returns to the entrance. Full mode renders the 3D layer at 480×300 before compositing into 960×600; Low uses 240×150 before compositing into 480×300.

Save/reopen and cue snapshots preserve the viewpoint. Cues restore a stationary camera; start Cruise explicitly for motion. Older v6 sessions load at the new entrance because their scalar travel did not encode a navigable pose. Older fractal frame plans are rejected with a request to re-export. New plans record the current starting pose and constant cruise/turn settings; they do not replay the preceding manual flight. PNG and WebM capture record the currently displayed output.

## Music

Choose a local audio file, the synthetic dark-techno Demo beat, Microphone, or Use tab audio. For internet radio, open an official player such as [cliqhop IDM](https://somafm.com/cliqhop/) in a browser tab, start playback, then select that tab with audio sharing enabled. Availability varies by desktop browser. A tab with no audio track produces a clear error; files and microphone remain alternatives. Stop music releases the source. Active Demo, Microphone, and Tab Audio buttons expose their pressed state as well as their label, and all source controls point to the live status message. The source dock also shows the current beat step, active voices, and bounded response level while the Demo beat is running, making the visual/audio coupling legible during a set. A selected-scene response line and highlighted family meter make the beat level for the visual currently on stage explicit while browsing the full scope. Each active hit also adds a restrained accent at the stage perimeter, so the shared beat remains readable inside every visual without washing out the artwork; the perimeter cue follows a hysteresis-gated beat onset rather than sustained loudness, and both that cue and the shared transient effect lift are suppressed when Reduced motion is enabled. Response controls sensitivity. The Demo beat is a local four-on-the-floor pattern with a heavy kick, off-beat hats, clap backbeats, and a restrained sub pulse; its beat envelope also drives every visual family, including Fractal Flight.

Music analysis stays on the device. Microphone and shared-tab audio are analysed without speaker monitoring and are excluded from recordings. Local-file/demo audio can accompany WebM recording. The Record control shows elapsed capture time, and the output dock keeps the last capture outcome explicit: active, saved, returned no data, or failed. Audio-source controls visibly lock until a recording is stopped, so a captured soundtrack cannot silently diverge from the rehearsal. If capture setup or audio-track attachment fails before a recorder exists, the partial stream is stopped and the UI returns a clear still/frame-export fallback. If a recorder rejects Stop synchronously, or its capture track ends unexpectedly, capture is cleaned up and the same fallback is shown instead of leaving the controls locked. Native source setup also rejects and releases streams that return no usable audio track, while watching every returned track for an ended-source handoff. The report records the bounded source outcome (`idle`, `connecting`, `active`, `empty`, `ended`, or `failed`) separately from the manual observed check, and keeps the last eight source transitions (`FILE`, `MIC`, `TAB AUDIO`, `DEMO`, or `NO AUDIO`) so a failed handoff followed by a fallback remains visible without becoming permission proof. If a microphone permission or shared tab ends, the status names the ended source and offers another source. No station streams or third-party media are bundled. Sources must be reconnected after reopening a set; media itself is never saved in JSON. The modulation readout exposes smoothed overall energy plus low/mid/high frequency bands; scene mappings use those bands, not measured BPM or beat detection. The source dock also reports `14/14 VISUALS BEAT-LINKED` for the Demo beat (or `AUDIO-LINKED` for external sources), making complete beat coverage visible during a rehearsal. Its live fourteen-cell beat scope mirrors those bounded family responses, giving a quick visual check of the spread without introducing another modulation path. A compact `HITS / LAST` onset line records a capped counter and UTC timestamp for real source threshold crossings; it is rehearsal telemetry, not a promise of beat-grid accuracy. The rehearsal card mirrors that counter, last source, and UTC time as diagnostic evidence, with screen-reader chatter suppressed on steady hits. **Run beat check** in the rehearsal surface records a bounded wiring check for all fourteen mappings and the shared effect stack; it is explicit evidence of the connection contract, not a claim that every look is aesthetically successful or that a device is certified. On each hit, the beat also gives the shared effect stack a bounded transient lift (symmetry, echo, chroma, and glow); authored effect values remain unchanged. The kick adds a dedicated low-end body and a conservative bus compressor when supported, so the heavier hit gains weight without relying on a hotter master level. A held time-domain peak readout labels remaining headroom as `HEADROOM`, `HOT`, or `NEAR CLIP`; it is coarse rehearsal telemetry, not calibrated loudness. Loaded before/after reports call out a changed headroom envelope separately from a changed source.

## Output and limits

Saved rehearsal reports include the exact pass snapshot shown on the rehearsal card, so the 20-minute audio gate and 14/14 visual/timing evidence remain visible after export and report reload. The source dock also includes a bounded 20-minute progress meter and remaining-time label tied to active-source duration; both reset when the source is stopped, keeping a restarted run from looking continuous.
Loading a report also surfaces that stored pass snapshot in the preflight card, with the same level color and gate wording; pre-snapshot reports stay explicitly labeled as legacy.
The loaded pass and comparison lines name the same UTC capture time and optional setup label, and mark that historical line stale when the live instrument drifts.
The adjacent comparison line groups live drift into setup, transport, audio, timing, visuals, evidence, pass, and authored-set buckets so a handoff can see the mismatch at a glance.

Frame plans retain the selected profile's bounded performance status (`warming-up`, `within-target`, or `over-target`) and nominal frame budget beside any measured median/p95 samples; this is observation metadata, not an FPS or device-certification claim.

Rehearsal Preflight accepts an optional bounded Device label so exported reports can name a setup such as `Studio Mac · Chrome 152`; the report readout repeats that label for saved, reopened, and stale snapshots. It stays local metadata and does not replace the browser/runtime context or certify the device.

Full (960×600 / 60 target), Low (480×300 / 30 target), and opt-in HD (1920×1200 / 60 target) change real canvas dimensions and work budgets; the rates are targets, not measured guarantees. Julia uses a bounded WebGL orbit shader at the selected output size when a usable WebGL context is available, so HD can provide a genuinely denser backing surface on a capable browser. Browsers without that path fall back to a bounded CPU sampling grid (480×300 on Full, 640×400 on HD, 160×100 on Low), keeping filaments sharper than the former thumbnail without pretending the fallback is native detail. In Focus, usable WebGL can request a bounded 1440×900 backing surface for the Full profile and the CPU fallback may use a bounded 640×400 detail pass; the stage remains capped at twice its internal raster width instead of being stretched indefinitely. The 4D scene contains a real tesseract graph and projected Hopf fibers. Hyperbolic Loom uses true disk geodesics and Möbius isometries; it is not a regular tiling or curved-space ray marcher. Evolution Garden currently breeds bounded harmonic contours, not neural networks or organisms.

Capture still, WebM recording, and numbered PNG frame plans use the same visual/effect output. Exported stills, recordings, frame plans, folders, and PNGs carry the safe set name so a rehearsal’s assets remain attributable after export. Offline plans render 1–240 frames from a seeded start into a new folder where directory writing is supported; the folder also receives a `frame-output.json` marker with its set identity, status, and written/total counts so partial output is distinguishable from a complete batch. During a render, stage, audio, score, and mobile transport controls are visibly locked until completion or cancellation; the visible Cancel action stays disabled until the native folder chooser has returned a destination. They preserve setup and events, not a lossless live-buffer checkpoint. Cancel/failure restores a paused seeded preview plus the captured cue/completion position and measured timing; blackout and recovery stay dark. A folder write failure keeps the partial count, records the failed marker, and names still capture, WebM, or Frame plan as the immediate fallback in the progress line and toast. The output dock also reports rolling per-scene median and p95 draw time (plus heap size where the browser exposes it), scoped to the selected quality profile, and labels the p95 tail within or over the nominal target budget so a rehearsal can distinguish an observed result from an unmeasured target. This is not an FPS or device-certification claim. Old Phase field plans require re-export, while archived old measurements retain their original model identity.

The public preview is not full-v1 acceptance: sustained reference-device performance, native microphone/tab capture, native folder permission, and performer review remain open. The top status line summarizes set transport, connected audio source, and output activity so a rehearsal can be checked before it starts. The output dock also names the active renderer path and rendered dimensions (for example, `Julia · WebGL native 960×600`, `Julia · WebGL native 1920×1200`, or a bounded CPU fallback), so a quality comparison cannot confuse the output canvas with the internal raster. Rehearsal Preflight checks browser API availability, including an actually supported WebM MIME path and the WebGL path used by Fractal Flight, and performs a reversible local-storage probe without requesting permissions; its compact checklist shows which paths are available or need a fallback, gives the local alternative for each missing capability, and records the local check time, but it is not device evidence. The preflight card also shows the exact accepted WebM MIME path, or explicitly says that none was accepted, so a recording fallback has a concrete reason. When a capture is active, that same card switches to the exact MIME path used by the live recorder and returns to the last preflight result when the capture ends. A live pass snapshot on the same card condenses source state, the sustained audio-run/headroom gate, fourteen-family beat links, timing coverage/status, and manual observations; it stays `IN PROGRESS` or `ATTENTION` until the documented 20-minute run and every local gate are satisfied, and never claims device certification. Save report downloads a versioned local JSON snapshot of that check, coarse runtime context for comparison across named devices, the active renderer path and dimensions, readiness, scene/profile, cue plan, audio-band state, measured draw-time summary, the selected recording MIME path (preferring the active recorder path when a capture is underway), the bounded last-recording outcome (`active`, `saved`, `empty`, or `failed`), the bounded audio-source outcome (`idle`, `connecting`, `active`, `empty`, `ended`, or `failed`) plus the last eight source transitions, an optional bounded performer note, and structured manual observed outcomes for microphone, tab audio, recording, PNG folder output, and performance without embedding media or credentials. Load report accepts that downloaded JSON again and compares its set plan, scene, output profile, named device, captured runtime context, renderer path, capability path, recording outcome, audio source/outcome/history, coarse peak/headroom telemetry, measured performance summary, and observed outcomes with the current instrument without applying or storing the imported body. Performance comparison is bounded to sample count, median/p95, target and status; audio comparison uses source kind, lifecycle outcome, bounded transition history, and bounded peak/headroom, not momentary band values. Contradictory imported performance metadata, malformed runtime context, renderer dimensions, and unknown source labels/outcomes are rejected. After loading, the comparison keeps a compact live signature and changes to `current state changed` when transport, renderer path, source/outcome/history, recording outcome, preflight, observations, or measured performance moves; loading another report starts a fresh comparison. The report also carries an explicit manual evidence status (`not-started`, `in-progress`, or `complete`) so a handoff cannot confuse partial evidence with a finished checklist. The card shows a live count of recorded observations (for example, 2/5), the names of remaining outcomes, and the local time of the latest manual update to make unfinished rehearsal evidence attributable; Reset observations clears those manual flags and their timestamp for a fresh device pass while preserving the set, notes, and capability matrix. Observed outcomes are intentionally distinct from API availability and are never a certification claim. A small local metadata cache preserves the report timestamp, captured device label, signatures, capability matrix, observed checks and their latest update time, recording outcome, and check timestamp so a reload can label the last report `reopened`, restore the checklist, and re-check it against the current set; report contents remain in the downloaded file, not browser storage. Meaningful state, note, observed-check, recording, audio-source, renderer, or viewport changes mark the saved report as stale in the UI, while a seeded render that restores the original state leaves it valid. Notes and runtime context stay local; notes and renderer metadata are not a secret store and runtime fields are not a fingerprinting claim. See [verification](docs/releases/studio.md), [score and Fractal Flight evidence](docs/releases/performance-score.md), [roadmap](ROADMAP.md), and [algorithm research](docs/research/README.md).

The loaded comparison also checks the captured transport state (live, paused, complete, and active cue) and exposes the captured manual-evidence count/status separately from the live checklist, so a before/after handoff can show transport drift plus `0/5`, `3/5`, or `5/5` without implying browser permission proof. It can be dismissed with a guarded **Clear loaded** action that stays disabled until a snapshot exists; this removes only the in-memory snapshot and readout, leaving the live set and local report cache untouched.

HD is an opt-in native-output profile: on a usable WebGL browser, Julia renders directly at 1920×1200 instead of the Full profile's 960×600 surface; without WebGL it raises the bounded CPU fallback to 640×400. The larger backing surface costs more work, so unsupported browsers remain visibly labeled rather than appearing sharper than they are.

The output dock reports the selected native dimensions (`960×600` or `1920×1200`) and the Focus overlay repeats the same path, so a saved screenshot can be read against the actual render surface rather than its CSS display size. In Focus, Julia keeps the one-click `Use HD` correction visible whenever the non-HD profile is active, even before a resize event updates the scale measurement; entering or leaving Focus at the same size also refreshes that action immediately.

## Focus diagnostics

Focus mode repeats the active renderer path, internal dimensions, rolling frame timing, and the CSS display scale over the stage, so quality and performance diagnosis remain visible while the workbench and output dock are hidden. A `CSS upscale` label makes a large viewport stretch explicit (the screenshot can be larger than the render surface); a native-fit label means no browser enlargement is being applied. Full-profile Julia uses a bounded 1440×900 WebGL backing surface when available and reports the effective `WebGL backing upscale`; on the CPU fallback, Focus constrains the stage to at most twice the internal raster width and reports `CPU raster upscale`, preventing a low-resolution thumbnail from becoming a wall-sized blur. If that bounded fit is still large, the readout points to the HD quality control. Native output remains full-width. The CPU fallback names its bounded cause when known (`WebGL unavailable`, shader initialization failure, or context loss). Preflight probes an actual usable WebGL context, so a constructor-only capability result cannot hide the CPU fallback cause.

On a large display, choose HD when the Focus renderer readout confirms `Julia · WebGL native 1920×1200`; if it reports CPU fallback, the bounded raster cap still applies and softness is expected. In Rehearsal Preflight, `Run Full / HD A/B` captures three frames per profile and records the actual renderer path, backing-to-output dimensions, display scale, and median/p95 timing in the next saved report; the compact line shows compositing explicitly (for example, `CPU 640×400→960×600`) and adds `HD HIGHER DETAIL`, `HD REDUCES UPSCALE`, or `SAME BACKING DETAIL` so the quality choice is actionable and CPU limits stay visible. Loading a saved Julia report reuses that derived recommendation in the same readout, so an older handoff remains actionable without rerunning the probe. The probe is permission-free and diagnostic, not a browser or hardware certification.

## Source

`app.js` integrates scenes, audio, transport, persistence, and export; `core.mjs` contains deterministic simulation primitives; `advanced.mjs` implements fractal/4D/hyperbolic drawing; `mandelbox-flythrough.mjs` retains its historical filename and implements the bounded WebGL recursive passages; `fractal-navigation.mjs` supplies the matching world-distance and camera model; `effects.mjs` implements the bounded effect stack. Run `npm test`, `npm run build`, and `npm run check:dist` for source verification.
