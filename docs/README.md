## Control interface

`control.css` holds layout primitives and `control-skin.css` the light/dark controls. `control-chassis.css` retains the static fallback; `control-layout.mjs` and `control-layout.css` fit five resizable panels to the viewport in both layouts, without document scrolling. Long contents scroll inside panels. `panel-layout.mjs` owns bounded geometry and separate desktop/portrait preferences in `phosphor-panel-layout-v1`. Pointer, arrow-key, Home/End and reset operations share that geometry. Adjacent seams yield when needed, so Rhythm can claim substantial space.

`chassis-renderer.mjs` reuses the original owner-provided artwork (`public/ui/biomechanical-page-shell.png`, `biomechanical-page-portrait.png`, provenance in `public/ui/assets.json`), keeping junction bands intact and stretching straight sections. Complementary alpha at the desktop spine avoids doubled borders; only layout changes repaint the frame. Desktop catalog filters occupy one compact bottom-rail group; GitHub/Reset sit at the right. Portrait keeps filters inside Catalog. Panel menus use native top-layer popovers with viewport clamping.

Tall two-column windows put Look/Performance labels above full-width faders and bound the gaps between controls. Rhythm adapts to its actual available panel height: labels sit above the grid when there is room, while shorter panels retain compact rows. Family/Global switches share the heading so all four Global tracks remain above the setup footer. Representative viewport checks are recorded in the [evidence log](EVIDENCE.md#responsive-panel-contents-2026-10-12).

`public/fonts/Forum-Regular.ttf` supplies the local heading/logo font; the accompanying SIL OFL license is included in distribution through the preload’s `data-license` asset reference.

`control-theme.js` applies browser-local appearance before first paint, defaulting to dark mode when there is no saved choice. `control-ui.mjs` owns the native setup dialog, tabs, catalog filters and keyboard boundaries. Playback, persistence and locking remain in `control.mjs`.

`color-picker.mjs` provides the HSV plane, hue strip, hex/numeric inputs and preset palette list. Its static DOM preserves pointer capture and focus during edits. The shared optional set `palette` is a library ID or validated three-colour object; the control defaults old/missing values to Symbiosis. Show applies it to manual/autopilot triggers and runtime recovery; automatic palette drift is disabled while it is set. Authored look colours remain intact as data. Catalog colour changes update one SVG colour matrix immediately; images and the render queue remain intact. Variation previews also use the shared colours. Compact rhythm cells directly edit sixteenth-note positions in a stable selected bar. Clicking between existing quarter/eighth hits promotes the grid while preserving loop duration and existing hits. Live projects every independent loop into the same absolute four-beat bar and aligns all playheads. The label wraps at the longest track’s bar count without resetting shorter loop phases. Navigation or a step edit pins the selected bar; Live resumes following. Bar navigation reaches longer loops; track names open small timing/strength popovers, and the Rhythm menu holds preset, draft and override options. The panel never expands into a full editor. Popover key-up events retain the global held-Flash release path.

Playback status in `control.mjs` synchronizes the Look editor and catalog selection when the playing look ID changes, using the actual clip snapshot for both local and Stage playback. This observation never auditions a look or resets Autopilot timing. Subsequent live parameter updates retain the existing fader nodes; manually selected or edited drafts are left alone until playback changes to another look.

Catalog cards keep native disclosures for rating/edit actions, and extra look/performance controls live in their header menus. Set faders and manual preflight checkboxes retain stable DOM nodes through periodic updates. Audio source changes and mute belong to the stage; local Demo/Off and mute choices transfer when it opens. The synthetic demo is scheduled against the same `ShowClock` as the visual, mapped to audible AudioContext time. Its beat tracker is not fed back into that clock. Absolute beat subdivisions prevent a downbeat change from dropping demo notes; the pattern follows the current bar origin. The preview BPM popover and Audio tempo input share `setClock`; numeric tempo edits are saved, and pending Stage edits are shown immediately so rapid ± clicks accumulate. Input/file sources retain their original audio speed.

Bare Space is captured before focused controls to toggle transport pause; text entry and modifier shortcuts retain their normal behavior. `ShowClock` holds its exact fractional beat, Show stops automatic advances and shifts time-based glides on resume, and Control/Stage skip rendering until resumed. `presentPausedOutput` presents explicit output changes once, so emergency Blackout remains immediate. `AudioEngine` suspends the existing context and pauses file media without resetting either; resume fencing prevents scheduling against a pending or stale audio timestamp. Pause-related media `AbortError` does not discard the file. Runtime handoff preserves paused clock state.

## How a show runs

The **stage** window owns live playback: renderer, show controller, clock, autopilot, audio input and the beat tracker (AudioWorklet). The **control** window edits the set and runs local performance when no stage is connected; while connected it sends performer actions over a BroadcastChannel and shows the stage's state and a preview. Reloading the controls never stops the stage; the stage saves its runtime state every second and restores the current clip, energy, speed, shared controls and tempo after a reload.

The main preview runs `Show` through `ControlPreview` on the existing editor renderer at up to 30 Hz. It defaults to the current monitor's native dimensions through `display-resolution.mjs`, constrained by GPU dimensions; the former `phosphor-preview-resolution` preference is ignored. The preview's resolution button and Set settings select `options.outputResolution`: native (default for older sets), or a maximum long edge of 3840/2560/1920/1280/960 pixels. Both preview and Stage preserve aspect ratio and never upscale above native; the readout reports the actual output dimensions. With a previously granted Window Management permission, `ScreenDetailed.devicePixelRatio` separates physical display scale from page zoom and screen changes are observed. Without that grant, browser screen dimensions and DPR are used with a minimum 1× scale: a 1× screen never loses resolution when zoomed out, but exact hardware scale on an already zoomed Retina browser cannot be guaranteed by ordinary Screen APIs. Startup does not request a new permission. While the stage is live, the monitor uses its full-resolution stream and only the small Look editor renders at 480×270. All performer actions affect that local renderer when no stage is connected. Opening a stage transfers the playing snapshot (including unsaved live parameter changes), shared controls, energy, speed, clock phase, freeze/flash and autopilot settings. The monitor switches to the stage's live video feed; the editor remains independent while the stage is live. Stage closure resumes local performance from the final reported live state, restores the selected preview resolution and presents the restored frame before revealing the local canvas.

Configuration is available through the setup dialog. The optional **Lock settings** switch in that dialog is enabled only while a stage is connected and disables clip/set/audio/MIDI inputs, not grid triggers, performer faders, audition, exports or the checklist. It automatically clears when the stage disconnects. There is no mandatory Show/Prep mode.

- **Sets (v5, D68):** no pages. A set holds `looks` (own looks: `own-…` id, name, the authored look it came from, snapshot, a library palette ID, `custom` colours or none, transition), `ratings` (look id → 0–10 in half steps; malformed entries are dropped, ratings of unknown looks kept), `favorites` (look ids), `keys` (the 32 look ids on the grid keys, written by the control from the first 32 cards of its catalog view), an optional shared `palette` (library ID or three hex colours), legacy palette `mood` or any (`null`), shared master/hue/zoom/mirror, autopilot (`enabled`, `random`, `everyBars`, `handBackBars`, `favoritesOnly`, `minRating`), clock, options, MIDI and lineages. The optional v5 `rhythm` extension stores global/family patterns; own looks may store an explicit `rhythm` override. Older v5 sets receive authored defaults; unknown effect/family records survive validation as dormant data. v4 → v5 turns each page clip that differs from its authored look (family, preset, seed or parameters) into an own look (name, colours, transition kept) and carries ratings, the first page's mood and the old 2.1 MP default as native; v1/v2/v3 pass through v4. Local saves move to `phosphor-set-v5` without deleting older entries; unreadable originals keep their first backup.
- **Clock:** one monotonic beat, 120 BPM until it hears or is given a tempo. Following audio, it steers toward the tracker with slew-limited, forward-only corrections and holds tempo and phase through breakdowns; nudges set a latency offset. Taps switch to manual tempo. Enter marks beat 1 of the bar. Beat tracking assumes 4/4 at 100–150 BPM (half and double tempo fold in). Selecting the line input switches to manual tempo at the current BPM (D63: tracking missed its targets on CC-licensed DJ mixes); **Follow audio** re-enables it. Demo and rehearsal files keep following.
- **Default mode:** local performance starts at 120 BPM with autopilot and Random on. A stage opened from the controls inherits the current local performance; a standalone fresh stage begins on its own defaults. The stage's demo becomes audible once Chrome allows audio, after the first click or key there. The stage remembers the chosen audio source across reloads (a file comes back as the demo).
- **Local demo sound:** without a stage, the control window starts the same 120 BPM demo on the first click or key press. It creates no audio context before that interaction and requests no microphone access. Off disables automatic resumption until Demo beat is selected again; Mute file/demo silences the local demo. Opening or hearing from the stage stops the local demo (including pending startup); closing the stage resumes it if demo remains selected. Choosing line input or a rehearsal file also stops the local demo; those sources remain stage-owned.
- **Catalog (D65, D68):** `catalog.mjs` derives one entry per authored look from `scenes.mjs` plus one per own look (`id`, family, family number, index, name, the type's label as variant, snapshot, `own`) and sorts (favourites, then rating groups, then the editorial order of `catalog-curated.mjs`, generated by `scripts/curate.mjs` (D69), then family and preset order), rates, filters for autopilot and picks by weight. The control's catalog panel (`control-catalog.mjs`) keeps one card per look and only reorders cards when the pointer or focus has left the list, so a rating never moves the card under the pointer; after each sort it reports the visible order and the control stores its first 32 ids as `keys`. Thumbnails (`catalog-thumbs.mjs`) use palette-independent 512×288 WebP images. `catalog-previews.mjs` bundles all 328 authored looks; `node scripts/build-catalog-previews.mjs` regenerates them after renderer/preset changes. IDs and scene/preset/seed/parameter signatures are checked against the catalog. An SVG matrix maps the RGB basis image into the shared palette without re-rendering; this is an approximate catalog preview, while live output uses the real scene palette. Own looks and variations use one lazy 512×288 engine, warm-up plus 24 frames, idle slices and GPU fences; stale asynchronous encodes cannot replace newer edits. These images are cached for the session and recoloured by the same matrix. **Play** (`{ type: "look", id }`) fires the look at once; **Edit** opens it in the look editor.
- **Autopilot:** plays from the catalog: every look not rated 0, limited to favourites with `favoritesOnly` and to looks rated at least `minRating` (unrated count as 5), falling back to every playable look when that leaves nothing. On loudness events it raises energy by 0.2 (build), lifts energy by 0.3 and smoothly transitions in one bar to a fresh look on the downbeat (drop) or lowers energy by 0.3, halves speed and later moves to another look (breakdown); changes keep the show energy (D54) and the show palette, and come back by id after a stage reload. Picks are weighted by rating and avoid up to the last 24 looks while keeping more than half of the pool to choose from. Regular changes fade over 12 beats; drops keep a four-beat melt (D66). **Random** (default on) plays each look a uniformly random 8, 12 or 16 bars (status `duration`), mixes crossfade 60 % / dissolve 20 % / melt 20 %, and glides the live look's continuous, non-type parameters to a new target within ±12 % of each range around the saved values every eight bars (smoothstep, on a private copy); off, changes come every `everyBars` (8/12/16/32/64), walk the catalog best first, always crossfade, and parameters stay put. **Next** (`{ type: "next" }`: button, Shift+Space, MIDI `next`) schedules the pick a regular change would make on the next beat with the regular fade and restarts the duration; it is not a takeover and works with autopilot off. Manual look, energy, speed, parameter or palette input stops the drift; shared mixer-strip trims do not. It never changes master, mirror, blackout or flash.
- **Energy:** show state, not clip state (D54): the fader and autopilot's build/breakdown/drop moves survive clip triggers; a fresh show starts at its first clip's stored energy. Each family declares how its parameters move from calm to intense (additive or multiplicative slopes from the energy the clip was authored at) and which shared beat responses it takes: zoom punch and brightness pulse on the kick, optional injection into simulations. Flashes unlock above energy 0.8 and always pass the flash limiter.
- **Audio features (D61):** every stage source feeds one bus: low (35–250 Hz), mid (250–2500 Hz) and high (2500–12000 Hz) attack/release envelopes, onset, positive spectral flux and a discrete adaptive-threshold hit with a 120 ms refractory. The FFT is unsmoothed; the bus owns envelope smoothing and loudness normalization. Each gated family declares three `audio: [{ param, feature, amount }]` heroes in scene metadata; amounts are signed fractions of the schema range, capped at ±0.18, smoothed with 40 ms attack / 180 ms release, added after energy curves, then range-clamped. These never edit clips or change type. Trusted audio needs both source signal and tracker lock; on silence, Off or lost lock, the last trusted response smoothsteps out over two seconds while the clock kick comes back. Shared punch/pulse, hit-driven injection and the headliner camera kick use that same hand-back; flashes remain limited. Bloom can lift by at most 0.06 (and 12% of its set ceiling), never above the ceiling.
- **Palettes (D57):** 25 curated three-stop palettes, including Symbiosis, tagged warm/cold/acid/mono/deep/peak. A shared set palette keeps manual/autopilot triggers and runtime recovery on the chosen colours; automatic palette drift is disabled. For legacy callers without a shared palette, manual triggers adopt their look palette and autopilot retains the historical mood-based glides. Changes smoothstep over four beats through `params` actions and `Engine.setSnapshot`, without changing the set or bypassing the flash limiter. Hand-back pauses follow manual clip, energy, speed, parameter and palette input; master/hue/zoom/mirror trims leave autopilot running. Glide endpoints are decoded once and renderer updates occur only when an 8-bit colour changes (or parameters drift). Parameter updates resolve the actual live or safe snapshot after loads, so a rejected family cannot overwrite the preceding picture. Runtime recovery and control↔stage handoff carry the palette, current interpolated colours and remaining glide.
- **Transitions (D58):** optional v4 clip field `transition`: `auto` (default), `crossfade`, `cut`, `dissolve` or `melt`; unknown values fail validation, and export/import is lossless. The editor select sits beside Fade. Manual Auto resolves to Crossfade; crossfade and dissolve ease with smootherstep (6t⁵−15t⁴+10t³, D66). Cut overrides quantization to the downbeat and has zero fade. Autopilot Auto resolves to a seeded crossfade/dissolve/melt mix in Random mode and Crossfade in order, a seeded Melt/Dissolve choice in breakdowns, and one-bar Melt on drops; an incoming simulation family's warm-up holds the transition at zero (checked per simulation family by `test:browser`); explicit smooth choices survive, but Cut always resolves to Crossfade (D50). Load actions carry the resolved kind. The compositor shares the eased mix/noise mask with bloom; Melt feeds only the outgoing ungraded picture through a zoom/rotate/displacement warp, reusing the two echo/history targets (post echo resumes afterwards). Interrupted transitions freeze the current ungraded transition into an existing slot buffer, retaining at most two slots and keeping the limiter in the final picture path.
- **Energy-driven post (D56):** Set options are ceilings, not fixed effect strengths: bloom eases in above energy 0.1, echo above 0.15, chroma above 0.25, and grain/vignette above 0.3; each reaches its ceiling at energy 1. The new optional v4 fields default to grain 0.12 and vignette 0.15 without changing any existing set field; explicit zero disables either. The settings lock covers all five sliders. Grain changes with the render tick, fades out in blacks and highlights, and cannot lift blackout or master-zero frames. Bloom extracts highlights with a 0.8 threshold / 0.4 soft knee before the existing hue-preserving shoulder tonemap.
- **Picture precision:** slot visuals, bloom, echo/history and approved mix frames use `RGBA16F` when `EXT_color_buffer_float` is present, otherwise the existing `RGBA8` path. [Half-float linear filtering is core in WebGL2](https://registry.khronos.org/webgl/specs/latest/2.0/); a missing WebGL1 `OES_texture_half_float_linear` extension does not disable float pictures. Values stay display-encoded (not sRGB textures or newly linearised scene palettes). Simulation state, the limiter's float-bit mean codec and health readbacks remain `RGBA8`; previous-frame families retain their byte-quantized emitter inside the engine so faint feedback residue cannot become a new persistent attractor. Float pictures defer quantization to the output, with luminance-masked display dither.
- **Screens:** the stage defaults to native physical display resolution (including Retina pixels), constrained by GPU dimensions; an explicit saved output-resolution choice may reduce it. Math and raymarched families compose natively; fixed-aspect simulation families render a frame that is cover-cropped to other shapes. Visual shading uses full output resolution while simulation grids remain independent. Frames are paced at about 60 Hz; slow frames never reduce resolution or ray steps.
- **Pre-show check:** the stage reports whether it is started, fullscreen on an external screen, holding a wake lock and has shown the framing pattern; the control adds microphone permission, input signal, beat lock or manual tempo and GPU errors, plus a manual list (mains power, Do Not Disturb, sleep, Chrome's quit warning, screen resolution). The checklist remains visible; locking settings does not imply that the show acceptance checks passed.

## Performance and recovery

Simulation runs on a fixed 60 Hz clock with at most six catch-up ticks per frame; the speed trim scales it (½×, 2×). Smooth transitions keep at most two slots, then dispose the old one; the engine counts every texture it creates and the harness checks none leak. Each family compiles in parallel. A family whose shaders fail is isolated, not fatal: the show never schedules it again, and if it was on screen the stage cuts to another look autopilot may play (else the safe look, else any playable look; with nothing playable, blackout). A frame error loads the safe look instead of stopping the show. WebGL context loss rebuilds resources and restarts the latest seed.

## Save and export

- **Sets:** saved locally on every edit (never during playback) and exported as `.phosphor.json`. Export before rehearsal and before the show.
- **Rehearsal log:** per-minute frame timing (p50/p95/p99), errors, memory, budget, scene and tempo lock, exported from the pre-show panel.
- **Contact sheets** (`npm run contact`): looks, energy ladders (`--sheet ladder`), grayscale type distinctness (`--sheet types`) and owner palette curation (`--sheet palettes`: every library palette across the six gated families' first types at energy 0.5, PNGs, HTML and dim/faulty-render findings under `artifacts/contact/palettes/`).
- **Family timing** (`npm run timing -- --rig --family <id>`): every type at energy 0.95 for 30 s on the real stage at 1920×1080 (2.1 MP); per-type frame p50/p95/p99, GPU errors, non-finite inputs and governor steps. Passes only on the real GPU with every p99 ≤ 34 ms and no downgrade. Run it alone: other GPU load corrupts the timing.
- **Catalog performance sweep:** `node scripts/profile-families.mjs --types --frames 20` measures every declared variant on the native GPU; `--presets` measures every authored look. Add `--reference <commit>` to compare scene shaders against a fixed revision and `--width 3840 --height 2160` for 4K. Reports under `artifacts/performance/` include GPU/Chrome identity, median/p95 completed-frame times, CPU submission and errors. The probe retains native shader resolution, includes post-processing and disables asynchronous flash approval for a synchronous throughput measurement; it does not certify display cadence, transitions or venue acceptance. `node scripts/compare-family-pixels.mjs --reference <commit>` compares the optimized families' seeded output across energy levels; `--times` and `--impulse` exercise later times and rhythm rotation.
- **Performance evidence and curve maps:** [latest full family measurements](families/PERFORMANCE.md). `node scripts/check-curve-maps.mjs` exhaustively checks the shader's integer maps against the CPU reference. Differential pixel captures retain strict two-step channel tolerance, synchronous reads and GPU/non-finite checks; they skip redundant asynchronous health polling.
- **Beat tracking check** (`npm run beat:eval -- songs/*.mp3 [--constant-tempo] [--clicks]`): first lock, share of time locked, tempo spread and jumps, and phase against the kick: each beat is paired with the strongest 150–2000 Hz attack nearby and the most common offset over ±8 beats is scored (windows whose attacks disagree are reported as unscored). `--constant-tempo` (produced tracks, not mixes) also fits one tempo grid to the agreeing attacks and scores every beat against it. Calibrated on synthetic kicks (median 1 ms). `--clicks` writes the music with a click on every predicted beat to `artifacts/beat/`. Put music in `songs/`; Git ignores it.
- **Offline:** all assets are precached as one content-stamped generation. Releases remain pinned during a show. **Update app** opens the standalone `update.html`/`update.mjs` updater, reachable even through the older cache-first worker. It downloads a complete release and requests activation; `sw.js` refuses while any other app-scope window is open, including legacy controls and stages. With only the requesting updater remaining, activation claims it before navigating to the current controls. Saved sets in local storage are retained; no stale control tab remains to overwrite them on unload. Save unsaved clip edits first and navigate to the updater in the same tab; never update mid-show.

## Release operations

Vercel production (`fabianxvogts-projects/phosphor-performance`) is connected to `fabianxvogt/phosphor`, with `main` as its production branch and the repository root as its build root. Every push to `main` automatically builds and publishes the current instrument. Other branches do not auto-deploy (`vercel.json`). The GitHub Pages mirror was retired on 2026-10-08.

`vercel.json` installs with `npm ci`, then runs tests, typecheck, build and distribution verification before publishing only `dist`. A failed check leaves the previous production release live; inspect the commit's Vercel check and build log. GitHub Actions independently runs the full browser/contact suite. Keep Node 24 in the Vercel project settings. Do not deploy a stale local `dist`; retry the Git-backed deployment in Vercel instead. Local music, recordings, generated artifacts, secrets and provider metadata remain outside the distribution.

Production updates do not switch an already-open show: its offline generation stays pinned. Use **Update app** after saving edits and closing the other Phosphor windows; saved sets survive. Never activate an update mid-show.

## Show acceptance

The show gate is in the [roadmap](../ROADMAP.md): an eight-hour unattended run on the reference rig with recorded mixes through the line input (`npm run soak -- --rig --minutes 480 --audio mix.wav`), output-measured blackout latency, a crash drill and a line check with a real DJ mixer. Not yet executed.

After `npm run build`, run `npm run blackout -- --trials 20` for a built-in-display smoke, or `npm run blackout -- --rig --screen <index> --trials 20` on the real-GPU external output. Screen indices are zero-based and listed at startup. Both runs use headed installed Chrome, fullscreen stage, real Blackout button input and a separate entire-screen capture page; macOS must grant Chrome **Screen & System Audio Recording** permission. The runner enumerates displays before choosing Chrome's capture source name (`Entire screen` for a single display), verifies the captured screen with white/black calibration, measures its delivery latency separately, and reports raw per-trial milliseconds/display frames plus median/p95/max in `artifacts/blackout/summary.json`. PASS means the worst raw latency is within two measured display intervals plus the explicitly reported median calibration allowance; calibration max is reported separately and never expands the allowance. No latency is silently subtracted. This measures compositor output, not panel or LED-processor latency; D63 still requires a phone slow-motion cross-check. The soak runner's engine-uniform telemetry alone is not output evidence.

Output quality (2026-10-10, INCREMENTAL): stage sizing uses native physical display pixels, with GPU dimension limits only; legacy set pixel budgets and the downgrade governor no longer constrain live output. Every family shades at full output resolution; authored simulation grids keep their own state sizes. Escape and Shift+Escape have no show action; Blackout and Safe look remain explicit buttons. Chrome reserves a long Escape hold to exit fullscreen, without changing playback. Verify popup closure, Retina sizing, audio handoff and native preview with `npm run test:stage-output` after building. Add `-- --native-gpu` for installed Chrome’s native GPU while retaining headless correctness assertions. Full-resolution external-display timing still needs rig verification.
