The offline frame plan is an executable `phosphor-frame-sequence-v2` seeded-start recipe. It strictly validates scene/preset/parameters, profile dimensions/cadence, settings, frame count (1–240), the fixed pre-step elapsed clock, and the bounded Evolution lineage snapshot before changing renderer state. The controller uses the existing `stepAndDraw` and brightness-correct output compositor at fixed `stepSeconds`, writes one PNG Blob at a time through a directory writer, reports only closed writes, and restores the prior session as a paused seeded restart. Active cues, audio/microphone, recording, transitions, graphics recovery, and Magnetic replay block a run. Cancellation and write/encode failure restore the session; no live buffer, audio, cue timer, or exact mid-run checkpoint is restored. Each directory run claims a new output subfolder so existing files are not overwritten. Legacy `phosphor-frame-sequence-v1` recipes are recognized as non-executable and rejected with a useful migration message. Folder output is unavailable on browsers without the directory picker; still/WebM/plan outputs remain available.

The shared import path validates and sanitizes a complete candidate before committing state, migrates valid three-scene `phosphor-set-v1` saves by filling new defaults, applies authored preset payloads during cue transitions, scopes gestures to the active scene, records bounded Phase setup/events, archives one explicitly captured Phase measurement with a versioned identity and event position, and records child parameter snapshots for Evolution promotion. Reopen/import resets live Phase buffers but preserves the validated archived snapshot; the compact native inspector shows live current and saved capture separately. Phase exports carry both and explicitly do not claim a lossless mid-buffer checkpoint. Context-loss recovery resets the active bounded renderer after restoration. The public recheck covered save/reload but not native file import or malformed-file recovery.
