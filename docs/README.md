## Classification

**INCREMENTAL / EMPIRICAL.** A product rebuild, not a research novelty claim. Seventeen scene modules are implemented (the sixteen planned families plus Evolution Garden until Acid absorbs it); none is a placeholder. Six have passed the family gate (Feedback, Tapestry, Cathedral, Interference, Pulse Geometry, Fractal Flight; [status](../ROADMAP.md#family-gate-status)); the rest are drafts. Mathematical/biological discovery, topology preservation, automatic musical understanding and cross-device exact replay are not claimed. State: production candidate; rig rehearsal and multi-hour endurance gates remain open.

## How a show runs

The **stage** window owns live playback: renderer, show controller, clock, autopilot, audio input and the beat tracker (AudioWorklet). The **control** window edits the set and runs local performance when no stage is connected; while connected it sends performer actions over a BroadcastChannel and shows the stage's state and a preview. Reloading the controls never stops the stage; the stage saves its runtime state every second and restores the current clip, energy, speed, shared controls and tempo after a reload.

The main preview runs `Show` through `ControlPreview` on the existing editor renderer at 480×270 / 30 Hz, without an extra WebGL engine. All performer actions affect that local renderer when no stage is connected. Opening a stage transfers the playing snapshot (including unsaved live parameter changes), shared controls, energy, speed, clock phase, freeze/flash and autopilot settings. The monitor switches to the stage's live video feed; the editor remains independent while the stage is live. Stage closure or heartbeat loss resumes local performance from the last reported live state.

Configuration is always visible and editable by default. The optional top-bar **Lock settings** switch is enabled only while a stage is connected and disables clip/set/audio/MIDI inputs, not grid triggers, performer faders, audition, exports or the checklist. It automatically clears when the stage disconnects. There is no mandatory Show/Prep mode.

- **Sets (v4):** 8 pages × 32 slots, with a page mood or any palette (`null`). A clip stores family, parameters, seed, a library palette ID or `custom` colours, authored energy, fade (beats), start quantization and whether autopilot may play it. Library IDs normalise `snapshot.palette` to the library's colours; the engine still reads the snapshot. New sets have varied palettes and the gated families on page 1; drafts wait on **Lab** with autopilot off (D55). **Add missing families** fills empty Lab slots. Shared master, hue, zoom, mirror and speed remain a mixer strip. v3 migration retains every clip and colour as `custom`; local saves move to `phosphor-set-v4` without deleting the old entry, and unreadable originals keep their first backup. v1/v2 scores pass through v3: cues become clips, while keyframes, audio routings and score-only MIDI targets are reported as dropped.
- **Clock:** one monotonic beat, 120 BPM until it hears or is given a tempo. Following audio, it steers toward the tracker with slew-limited, forward-only corrections and holds tempo and phase through breakdowns; nudges set a latency offset. Taps switch to manual tempo. Enter marks beat 1 of the bar. Beat tracking assumes 4/4 at 100–150 BPM (half and double tempo fold in). Selecting the line input switches to manual tempo at the current BPM (D63: tracking missed its targets on CC-licensed DJ mixes); **Follow audio** re-enables it. Demo and rehearsal files keep following.
- **Default mode:** local performance starts at 120 BPM with autopilot and Random on. A stage opened from the controls inherits the current local performance; a standalone fresh stage begins on its own defaults. The stage's demo becomes audible once Chrome allows audio, after the first click or key there. The stage remembers the chosen audio source across reloads (a file comes back as the demo).
- **Local demo sound:** without a stage, the control window starts the same 120 BPM demo on the first click or key press. It creates no audio context before that interaction and requests no microphone access. Off disables automatic resumption until Demo beat is selected again; Mute file/demo silences the local demo. Opening or hearing from the stage stops the local demo (including pending startup); closing the stage resumes it if demo remains selected. Choosing line input or a rehearsal file also stops the local demo; those sources remain stage-owned.
- **Autopilot:** plays allowed clips on the current page every 16/32/64 bars, never repeats the last six, and on loudness events raises energy by 0.2 (build), lifts energy by 0.3 and crossfades in one bar to a fresh clip on the downbeat (drop) or lowers energy by 0.3, halves speed and later moves to a calmer clip (breakdown); clip changes keep the show energy (D54). Every autopilot change crossfades (at least two bars). **Random** (default on) picks regular changes at random and glides the live clip's continuous, non-type parameters to a new target within ±12 % of each range around the saved values every eight bars (smoothstep, on a private copy; the set is untouched); off, changes walk the page in slot order and parameters stay put. Manual clip, energy, speed, parameter or palette input stops the drift; shared mixer-strip trims do not. It never changes master, mirror, blackout, flash or page.
- **Energy:** show state, not clip state (D54): the fader and autopilot's build/breakdown/drop moves survive clip triggers; a fresh show starts at its first clip's stored energy. Each family declares how its parameters move from calm to intense (additive or multiplicative slopes from the energy the clip was authored at) and which shared beat responses it takes: zoom punch and brightness pulse on the kick, optional injection into simulations. Flashes unlock above energy 0.8 and always pass the flash limiter.
- **Palettes (D57):** 24 curated three-stop palettes, tagged warm/cold/acid/mono/deep/peak. A manual trigger adopts its clip's palette; an autopilot trigger keeps the current show palette. Both autopilot modes step to a page-mood palette every 64–128 bars, avoiding the last three, and to a contrasting palette on drops. Changes smoothstep over four beats through `params` actions and `Engine.setSnapshot`, without changing the set or bypassing the flash limiter. Hand-back pauses follow manual clip, energy, speed, parameter and palette input; master/hue/zoom/mirror trims leave autopilot running. Glide endpoints are decoded once and renderer updates occur only when an 8-bit colour changes (or parameters drift). Parameter updates resolve the actual live or safe snapshot after loads, so a rejected family cannot overwrite the preceding picture. Runtime recovery and control↔stage handoff carry the palette, current interpolated colours and remaining glide.
- **Energy-driven post (D56):** Set options are ceilings, not fixed effect strengths: bloom eases in above energy 0.1, echo above 0.15, chroma above 0.25, and grain/vignette above 0.3; each reaches its ceiling at energy 1. The new optional v4 fields default to grain 0.12 and vignette 0.15 without changing any existing set field; explicit zero disables either. The settings lock covers all five sliders. Grain changes with the render tick, fades out in blacks and highlights, and cannot lift blackout or master-zero frames. Bloom extracts highlights with a 0.8 threshold / 0.4 soft knee before the existing hue-preserving shoulder tonemap.
- **Picture precision:** slot visuals, bloom, echo/history and approved mix frames use `RGBA16F` when `EXT_color_buffer_float` is present, otherwise the existing `RGBA8` path. [Half-float linear filtering is core in WebGL2](https://registry.khronos.org/webgl/specs/latest/2.0/); a missing WebGL1 `OES_texture_half_float_linear` extension does not disable float pictures. Values stay display-encoded (not sRGB textures or newly linearised scene palettes). Simulation state, the limiter's float-bit mean codec and health readbacks remain `RGBA8`; previous-frame families retain their byte-quantized emitter inside the engine so faint feedback residue cannot become a new persistent attractor. Float pictures defer quantization to the output, with luminance-masked display dither.
- **Screens:** the stage renders at the screen's native size within a pixel budget (2.1 / 1 / 0.5 MP). Math and raymarched families compose natively; simulation families render a 16:9 frame that is cover-cropped to any other shape. Frames are paced at about 60 Hz whatever the display's refresh rate. Two consecutive slow five-second windows first lower a raymarched family's step budget (96 → 64 → 40, remembered per family), then the pixel budget; nothing steps back up during a night, and the rehearsal log counts both.
- **Pre-show check:** the stage reports whether it is started, fullscreen on an external screen, holding a wake lock and has shown the framing pattern; the control adds microphone permission, input signal, beat lock or manual tempo and GPU errors, plus a manual list (mains power, Do Not Disturb, sleep, Chrome's quit warning, screen resolution). The checklist remains visible; locking settings does not imply that the show acceptance checks passed.

## Performance and recovery

Simulation runs on a fixed 60 Hz clock with at most six catch-up ticks per frame; the speed trim scales it (½×, 2×). Crossfades keep at most two slots, then dispose the old one; the engine counts every texture it creates and the harness checks none leak. Each family compiles in parallel. A family whose shaders fail is isolated, not fatal: the show never schedules it again, the control grid strikes its clips through, and if it was on screen the stage cuts to a playable clip on the page (else the safe look, else any page; with nothing playable, blackout). A frame error loads the safe look instead of stopping the show. WebGL context loss rebuilds resources and restarts the latest seed.

## Save and export

- **Sets:** saved locally on every edit (never during playback) and exported as `.phosphor.json`. Export before rehearsal and before the show.
- **Rehearsal log:** per-minute frame timing (p50/p95/p99), errors, memory, budget, scene and tempo lock, exported from the pre-show panel.
- **Contact sheets** (`npm run contact`): looks, energy ladders (`--sheet ladder`), grayscale type distinctness (`--sheet types`) and owner palette curation (`--sheet palettes`: every library palette across the six gated families' first types at energy 0.5, PNGs, HTML and dim/faulty-render findings under `artifacts/contact/palettes/`).
- **Family timing** (`npm run timing -- --rig --family <id>`): every type at energy 0.95 for 30 s on the real stage at 1920×1080 (2.1 MP); per-type frame p50/p95/p99, GPU errors, non-finite inputs and governor steps. Passes only on the real GPU with every p99 ≤ 34 ms and no downgrade. Run it alone: other GPU load corrupts the timing.
- **Beat tracking check** (`npm run beat:eval -- songs/*.mp3 [--constant-tempo] [--clicks]`): first lock, share of time locked, tempo spread and jumps, and phase against the kick: each beat is paired with the strongest 150–2000 Hz attack nearby and the most common offset over ±8 beats is scored (windows whose attacks disagree are reported as unscored). `--constant-tempo` (produced tracks, not mixes) also fits one tempo grid to the agreeing attacks and scores every beat against it. Calibrated on synthetic kicks (median 1 ms). `--clicks` writes the music with a click on every predicted beat to `artifacts/beat/`. Put music in `songs/`; Git ignores it.
- **Offline:** all assets are precached as one content-stamped generation. Releases remain pinned during a show. **Update app** opens the standalone `update.html`/`update.mjs` updater, reachable even through the older cache-first worker. It downloads a complete release and requests activation; `sw.js` refuses while any other app-scope window is open, including legacy controls and stages. With only the requesting updater remaining, activation claims it before navigating to the current controls. Saved sets in local storage are retained; no stale control tab remains to overwrite them on unload. Save unsaved clip edits first and navigate to the updater in the same tab; never update mid-show.

## Release operations

Vercel production (`fabianxvogts-projects/phosphor-performance`) is the only public deployment, published from reviewed `dist` at checkpoints, never mid-show. The GitHub Pages mirror was retired on 2026-10-08. For manual Vercel updates: `npm run build && npm run check:dist`, then `npx vercel link --yes --project phosphor-performance --scope fabianxvogts-projects --cwd dist` and `npx vercel deploy --prod --yes --scope fabianxvogts-projects --cwd dist`. Builds recreate `dist`, including the upload exclusion policy; re-link after rebuilding. Only deploy reviewed distribution assets. `.env*`, `.vercel`, other-provider metadata and the exclusion file itself are excluded; never publish CLI-generated environment tokens. Git connection is intentionally not required, avoiding an automatic deployment of the separate default-branch instrument.

## Show acceptance

The show gate is in the [roadmap](../ROADMAP.md): an eight-hour unattended run on the reference rig with recorded mixes through the line input (`npm run soak -- --rig --minutes 480 --audio mix.wav`), output-measured blackout latency, a crash drill and a line check with a real DJ mixer. Not yet executed.

After `npm run build`, run `npm run blackout -- --trials 20` for a built-in-display smoke, or `npm run blackout -- --rig --screen <index> --trials 20` on the real-GPU external output. Screen indices are zero-based and listed at startup. Both runs use headed installed Chrome, fullscreen stage, real Escape input and a separate entire-screen capture page; macOS must grant Chrome **Screen & System Audio Recording** permission. The runner enumerates displays before choosing Chrome's capture source name (`Entire screen` for a single display), verifies the captured screen with white/black calibration, measures its delivery latency separately, and reports raw per-trial milliseconds/display frames plus median/p95/max in `artifacts/blackout/summary.json`. PASS means the worst raw latency is within two measured display intervals plus the explicitly reported median calibration allowance; calibration max is reported separately and never expands the allowance. No latency is silently subtracted. This measures compositor output, not panel or LED-processor latency; D63 still requires a phone slow-motion cross-check. The soak runner's engine-uniform telemetry alone is not output evidence.
