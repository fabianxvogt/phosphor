# Cue labels and timing

2026-09-16. **Local source improvement.** Classification: **INCREMENTAL / EMPIRICAL**.

## Change

Each cue in the set editor now exposes a paused preview/recall action, snapshot-preserving duplication, bounded name, adjacent move controls, and an integer duration field from 1–64 bars. The set itself also has a bounded name that round-trips through portable JSON with an `Untitled set` fallback; JSON exports use a safe, bounded version of that name in the downloaded filename. Editing and ordering are persisted with the existing portable session format, immediately update the total clock-and-bars readout, and are rejected while a set is live so a performer cannot accidentally retime, reorder, or rename the active transport. The cue list uses explicit list/listitem semantics with position metadata, and the selected rehearsal step is exposed with `aria-current="step"` so active state does not depend on the acid-green border alone. When a preview or running set advances, the active row uses a nearest-edge scroll reveal without stealing keyboard focus, keeping long-set navigation oriented. The footer separately names the active cue, shows its remaining time, and labels the transport LIVE or PAUSED, keeping the cue-level clock distinct from aggregate set progress. After the last cue, the footer and readiness line stay at COMPLETE and the transport button changes to Restart set until pressed again, making the restart handoff explicit without persisting transient transport state. Removing a non-current cue preserves the paused active cue; removing the active cue intentionally clears its position. Invalid entries are restored to the last valid value by the cue list; shortening a paused current cue below its elapsed position advances to the next cue on resume. Loading the authored 24-minute score applies the replacement before exporting, so the downloaded JSON now matches the score shown on screen. Session import also clears the canceled transport handle, so offline output can start immediately after a paused rehearsal.

The top status line also summarizes the current transport (`READY`, `SET LIVE`, or `SET PAUSED`), source (`NO AUDIO`, `FILE`, `MIC`, `TAB AUDIO`, or `DEMO`), and output (`OUTPUT READY`, `RECORDING`, or `PNG RENDER`). It is a truthful readiness cue, not a promise that browser permissions or sustained device performance have been tested. Source and recording mutations synchronize this line immediately, even when the stage is paused, so the output state does not wait for a render frame. Demo, Microphone, and Tab Audio controls expose active/inactive state and point to the live audio status, while the file source shares the same description. The Record control shows elapsed capture time while WebM capture is active; the output dock retains the last bounded recording outcome (`active`, `saved`, `empty`, or `failed`), and the preflight card names the exact MIME path being used during that capture before restoring the last preflight result on stop. If capture-stream setup or audio-track attachment throws before a recorder exists, partial tracks are stopped and the UI returns a clear still/frame-export fallback. If a recorder rejects Stop synchronously or a capture track ends unexpectedly, the capture is cleaned up and the same fallback is shown rather than leaving the source controls locked. Native microphone/tab setup also releases streams with no usable audio track, marks the source outcome as `empty` or `failed` when appropriate, and watches every returned track for an ended-source handoff. The rehearsal report retains the last eight source transitions, attributing an empty or ended handoff to the source kind without persisting media. Source-change controls are visibly disabled until recording finalizes, keeping the recorded soundtrack attributable to the source shown at capture start. Dirty local sessions flush synchronously on page hide, and the portable-session heading announces the latest local-save time. Offline PNG rendering also locks the source, score, response, and mobile transport controls until completion or cancellation; its visible Cancel action is disabled while the native folder chooser is still pending, then enabled for the actual render. Native output folders receive a `frame-output.json` completion marker with the set identity and written/total counts, including canceled or failed partial-output status; when a write fails, the progress line and toast retain the partial count and point to still capture, WebM, or Frame plan. All downloaded visual assets now carry the bounded safe set name; frame-folder files use the same identity while retaining scene and frame numbering.

Rehearsal Preflight checks those browser APIs, verifies that at least one WebM MIME path is accepted, shows the exact accepted path (or an explicit no-path result), checks the WebGL API needed for Fractal Flight, and performs a reversible local-storage probe without opening permission prompts. Its checklist marks each path as available or fallback, gives a concrete local route for every missing capability (for example Demo beat/local audio, Capture still/Render PNGs, Frame plan/WebM, JSON backup, or a 2D scene), and records the local check time, so a performer can choose the documented alternative; it does not replace a real browser/device rehearsal.

The stage overlay now mirrors that transport vocabulary (`LIVE`, `SET LIVE`, `SET PAUSED`, `SET COMPLETE`, `PAUSED`, `BLACKOUT`, or `RECOVERING`) so a paused cue preview is not visually mistaken for an unqualified live set. During a scene transition it keeps both facts visible, for example `SET LIVE · MORPHING`; a global visual pause takes precedence so the canvas state remains truthful.

The WebGL preflight entry probes an actual usable context rather than relying only on a global constructor; the stage and output readouts still provide the definitive Julia path and internal dimensions for the current frame.
