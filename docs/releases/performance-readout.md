# Performance readout

The output dock now reports a rolling per-scene frame-time median and p95 once a scene has accumulated samples. Timings wrap the actual scene draw and are kept separate for the Full, Low, and HD output profiles. The median averages the two middle samples for an even window; p95 uses a conservative nearest-rank sample so a slow tail is not hidden. When the browser exposes `performance.memory`, the current heap size is shown alongside those timings. The readout also compares the p95 tail with the selected profile's nominal frame budget and labels it `within target` or `over target`; before samples exist it says `warming up` with the target budget. A neighboring renderer readout names the actual path and internal dimensions, making Julia's native WebGL output distinguishable from its bounded CPU fallback rather than hiding an upscale behind the output-canvas label. This comparison is a bounded observation, not an FPS claim or certification, and the same status/target metadata is included in rehearsal reports and exported frame plans; renderer path evidence is included in rehearsal reports for GPU-versus-CPU comparison.

HD is now an explicit opt-in output profile (`1920×1200 · 60 target`). When Julia reports native WebGL, that profile increases the actual shader backing surface; when WebGL is unavailable, the normal CPU path uses a bounded 640×400 raster. Focus uses a bounded 720×450 Full detail pass or 960×600 when HD is selected, while the stage cap keeps the displayed width from growing beyond the output surface. The Full-profile CPU path normally uses a bounded 480×300 raster, so the sharper Focus pass does not change the normal Full budget. Fractal Flight now uses bounded profile-aware WebGL backings (640×400 Full, 720×450 Focus, 1280×800 HD, 240×150 Low) instead of a fixed 480×300 thumbnail, reducing enlargement while keeping ray-march work below the output canvas; Focus also caps the visible stage at 1.5× its backing width. Seeded offline frame plans deliberately ignore transient Focus enlargement and use the canonical profile backing, then repaint the restored Focus view at its quality size. Full-profile Focus WebGL likewise uses a bounded 1440×900 backing cap (with the canonical HD profile remaining 1920×1200), so a large stage no longer enlarges only a 960×600 shader frame; Low remains 160×100. This supports the open reference-device gate in [the roadmap](../../ROADMAP.md). A real rehearsal should record the browser, device, quality profile, scene, effects, and observed readout; the local automated suite only verifies bounded rendering and deterministic state transitions.

Local Chrome smoke on `http://localhost:48101/` also confirmed the output dock keeps the target comparison legible beside the capture controls, while the Rehearsal Preflight card keeps manual evidence controls separate from the capability check. This is layout/browser smoke evidence, not sustained-device or performer evidence.

Focus mode repeats the renderer, rolling frame-time, and CSS display-scale readouts on the stage overlay, where the output dock is intentionally hidden, so a full-screen rehearsal still exposes whether Julia is using native WebGL or the bounded CPU fallback, whether the measured tail is within target, and whether the viewport is enlarging the render surface. Focus now caps every visual family to its native output width by default, so a 960×600 Canvas 2D scene is not silently stretched across a wall-sized viewport. Full-profile Focus WebGL reports the effective scale of its bounded 1440×900 backing surface; a CPU Julia fallback still constrains the Focus stage to at most twice its internal raster width and reports the effective CPU-raster scale, preventing either path from being silently enlarged across the screen. When a non-HD Julia frame is still being enlarged beyond that bounded fit, the overlay adds an `HD available` hint pointing back to the quality control instead of changing the profile automatically.

The CPU fallback readout names a bounded cause when known (`WebGL unavailable`, shader initialization failure, or context loss). Preflight probes an actual usable WebGL context rather than only checking for a global constructor; it still does not compile the Julia shader or certify a device.
