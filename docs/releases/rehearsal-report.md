# Rehearsal report

2026-09-17. **Local source improvement.** Classification: **INCREMENTAL / EMPIRICAL**. No media, credential, or device-performance claim is implied.

## Change

The card now also accepts an optional bounded **Device label** (for example, `Studio Mac · Chrome 152`). It is stored with the portable set and report, repeated in the saved/reopened/stale report readout, marks an existing report stale when changed, and supplements—not replaces—the bounded runtime context. This gives repeated rehearsals a human-readable setup name without treating it as a fingerprint or certification.

Reports can also carry an optional permission-free `phosphor-beat-response-v1` check. **Run beat check** applies a fixed transient in memory, records the fourteen scene IDs, their mapped low/mid/high band and bounded response level, plus each shared effect's authored/pulsed values. It restores the original pulse immediately and is explicitly wiring evidence, not proof of audio hardware, device performance, or aesthetic intent. Loaded reports compare this payload as `beat response` so a fresh check cannot be mistaken for an older one.

The Rehearsal Preflight card now has permission-free **Save report** and **Load report** actions. Save downloads a versioned `phosphor-rehearsal-report-v1` JSON snapshot containing bounded runtime context (truncated user-agent, language, viewport, pixel ratio, hardware concurrency, and touch capability), the bounded set identity, an optional performer-entered rehearsal note, current scene and preset, output profile and dimensions, readiness line, the accepted WebM MIME path (or an explicit `null` when no candidate is accepted; an active recorder path takes precedence while capturing), a bounded last-recording outcome (`active`, `saved`, `empty`, or `failed`), a cue-plan summary (labels, scenes, looks, durations, and active transport position), the most recent capability matrix and local check timestamp, rolling scene draw-time summary, optional heap telemetry, low/mid/high audio-band state, a structured set of manual observed checks for microphone, tab audio, recording, PNG folder output, and performance, and an explicit manual evidence status (`not-started`, `in-progress`, or `complete`). The status means only how many manual outcomes have been recorded; it is not a certification. The card also shows a live count of recorded observations, names the remaining outcomes, and shows the local time of the latest manual update so unfinished evidence is visible and attributable before export. Load validates that downloaded snapshot without requesting permissions, changing the set, or persisting the imported body, then reports whether the set plan, scene, profile, named device, captured runtime context, capability path, recording outcome, audio source/outcome/history, measured performance summary, and observed outcomes match the current instrument. Performance comparison uses bounded sample/median/p95/target/status fields; audio comparison uses only the source kind, lifecycle outcome, and last eight source transitions, never band values that can change moment to moment. Contradictory imported performance status, malformed runtime context, or unknown source labels/outcomes are rejected. Once loaded, the comparison keeps a compact live signature and changes to `current state changed` when transport, source/outcome/history, recording outcome, preflight, observed checks, or measured performance moves; loading another report starts a fresh comparison. A **Reset observations** action clears only those manual flags and their timestamp for a fresh device pass; it preserves set state, notes, and the capability matrix and marks any saved report stale. Observed checks are deliberately performer-entered evidence; they do not certify browser APIs, permissions, or device behavior. The report records only the connected source kind (`FILE`, `MIC`, `TAB AUDIO`, `DEMO`, or `NO AUDIO`) plus its bounded lifecycle outcome (`idle`, `connecting`, `active`, `empty`, `ended`, or `failed`) and a bounded transition history; it never serializes media, file contents, streams, or credentials. Runtime context is local evidence for comparing named-device rehearsals, not a fingerprinting or security claim. Notes are capped at 1,000 characters, stored in the portable set, and remain local; they are for rehearsal outcomes, not secrets. If no check has run yet, exporting runs the same non-prompting preflight first. A compact local cache keeps the report timestamp, captured device label, signatures, capability matrix/check timestamp, recording MIME detail, recording outcome, and observed-check metadata including its latest update time—never the downloaded report body—so a reload can show `reopened`, restore the checklist, and re-check the evidence against the current set. After saving, meaningful set or imported visual-state, transport, source/outcome/history, graphics, preflight, note, observed-check, recording, or viewport changes mark the readout `state changed` immediately, while repeated cleanup with no active capture and unchanged cue/set edits leave it fresh, so an old snapshot cannot be mistaken for the current rehearsal. The stale label stays tied to the captured report even if the current Device label is edited. The live freshness check compares only a compact transport/environment signature per frame; full authored-state serialization is reserved for export/import boundaries. A seeded PNG render temporarily owns the controls but does not invalidate a report when the original state is restored. The actions are locked while rendering, matching the other rehearsal controls.

The source dock now includes a bounded 20-minute progress meter and visible remaining-time label tied to the same active-source duration used by the pass snapshot. Stopping or switching sources resets both, so an interrupted run cannot look continuous.

It also summarizes distinct source paths seen or attempted in the bounded local history. Seeing two or more paths is labeled as multiple paths seen; this remains rehearsal evidence and does not prove that every path became active, permission, or hardware behavior.

The same live line is mirrored visually in the Rehearsal Preflight card, keeping current source context beside the pass summary when the lower source dock is not visible. Loading a report also exposes a separate historical source-history line with its last recorded outcome. Imported reports retain their own bounded history for comparison; the live mirror is not restored from a report.

The loaded comparison also checks the captured transport state (live, paused, complete, and active cue) and exposes the captured manual-evidence count/status separately from the live checklist, so a before/after handoff can show transport drift plus `0/5`, `3/5`, or `5/5` without implying browser permission proof. While a local WebM capture is active, the preflight card temporarily names the MIME path selected by that recorder; stopping or cleaning up restores the most recent preflight result, so the report's capability detail never masquerades as a stale active path. The output dock and report retain the bounded last-recording outcome, and an ended capture track is treated as a failed attempt with the same still/frame-export fallback rather than a silent success. Capture-stream or audio-track setup failures before recorder creation now stop partial tracks and leave that readout unchanged, with a still/frame-export fallback. Folder-render write failures preserve the partial count and surface the same fallback routes in the progress line and toast, while still writing the failed completion marker when possible. It can be dismissed with a guarded **Clear loaded** action that stays disabled until a snapshot exists; this removes only the in-memory snapshot and readout, leaving the live set and local report cache untouched.

Report validation now treats the output profile as a contract: the profile ID must be one of the known Full, Low, or HD profiles, and its width, height, and cadence must agree with the captured fields. This prevents a hand-edited report from labeling a soft or mismatched frame as HD.

Julia's `Run Full / HD A/B` action is also recorded in the report when captured. The bounded `phosphor-quality-ab-v1` payload stores three preview timings per profile, the actual renderer path and backing dimensions, the CSS display scale, and target status; its compact live summary shows backing-to-output compositing (for example, `CPU 640×400→960×600`) so Focus softness is not hidden behind the output canvas size. It stores no pixels, media, or fingerprint. Loading a report compares this evidence as `quality A/B` alongside renderer and performance, so a new device pass cannot be mistaken for the old one.

## Limits and next test

The report is a local snapshot, not a signed benchmark or proof of native permissions, sustained frame rate, memory headroom, or performer success. A saved `empty` or `failed` recording outcome is a concrete fallback signal, not a successful recording claim; the manual Recording observed-check remains independent and must only be marked after a performer verifies the result. Capture one report before and after a named-device rehearsal, mark the observed outcomes only after testing them, keep it with the exported set, and compare the observed profile, source path, recording outcome, and draw-time tail with the native microphone/tab/folder outcomes. Offline seeded rendering restores bounded measured timing and paused cue/completion transport state so a report remains attributable across a profile-swapped render.
